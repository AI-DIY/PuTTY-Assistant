为真实工作流而设计

少一次复制粘贴，多一层可控判断

开发、运维和技术支持人员经常需要在 SSH 终端、搜索结果和 AI 工具之间来回切换。PuTTY AI 将这些工作重新收拢到同一扇窗口：保留熟悉的终端操作方式，同时在需要时提供有上下文的分析。

它面向需要理解系统状态、排查异常或学习 Linux 命令的人。AI 可以给出建议，但执行权始终保留在操作者手中。

核心能力

终端旁边，是一个知道边界的 AI 助手

01

基于上下文的问题分析

终端上下文默认不发送。手动启用后，客户端会先尽力脱敏密码、令牌、授权头和私钥等信息。

02

日志与故障排查

用自然语言描述现象，结合终端输出梳理异常线索，并得到可逐步验证的排查建议。

03

流式中文多轮会话

支持 OpenAI Chat Completions 兼容接口。回复以流式方式出现，按主机隔离的对话可继续追问。

04

命令回填，而非代替操作

候选命令先解释用途与影响，再由用户确认回填。高风险命令额外需要二次确认，且不会自动发送 Enter。

工作方式

从终端信息到可复核的建议

PuTTY AI 不替代操作人员。它把问题、上下文、分析与确认连接起来，让每一个关键动作都有停下来判断的机会。

  1. 1

    用自然语言描述问题

    询问报错原因、系统状态、排查思路或命令用法。

  2. 2

    按需附带已脱敏的终端上下文

    上下文选择权在用户手中，默认不会发送当前会话内容。

  3. 3

    阅读流式分析与操作建议

    模型可以返回解释、排查步骤或候选命令，不强制每次输出命令。

  4. 4

    确认后回填到终端

    只将命令放入输入区域；发送与否仍由操作者决定。

隐私与安全

先控制上下文，再请求模型

对于远程系统操作，速度很重要，边界同样重要。PuTTY AI 将发送终端上下文、持久化模型配置和执行候选命令的决策留给用户。

  • 终端上下文默认关闭，启用前由用户主动决定。
  • 持久化 API Key 通过 Windows DPAPI 按当前用户加密。
  • 审计日志不记录问题、回复、终端上下文、命令正文或 API Key。
  • 删除、格式化、停服和改权限等高风险命令需要二次确认。

AI 输出仍可能出错。请在执行任何生成命令前人工复核，避免将本工具直接用于无人值守生产操作。

常见问题

使用前需要知道的事

PuTTY AI 是什么？

PuTTY AI 是在 PuTTY 0.84 源码基础上开发的 Windows AI 增强型 SSH 客户端。它将日志分析、命令解释和人工确认整合到终端旁边。

它会默认发送我的终端内容吗？

不会。终端上下文默认关闭；用户手动启用后，客户端会先尽力对密码、令牌、授权头和私钥等信息进行脱敏。

AI 会自动执行生成的命令吗？

不会。候选命令需要用户确认后才会回填到终端，且不会自动发送 Enter。高风险命令还需要二次确认。

这是 PuTTY 或 OpenAI 的官方产品吗？

不是。PuTTY AI 由独立开发者维护；PuTTY、OpenAI 和其他第三方名称仅用于说明兼容性、来源和许可证归属。
