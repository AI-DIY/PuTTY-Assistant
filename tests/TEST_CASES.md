# PuTTY-Assistant 全局功能测试用例（待审核）

> 状态：已审核，发布前执行全部适用测试并记录结果。
>
> 依据：根目录 `readme.md`、`putty-src/windows/ai.c`、现有 CMake 测试目标、`tests/run-integration.ps1` 和 `tests/run-remote-ssh.ps1`。

## 1. 测试约定

- 目标版本：Windows 10/11，Visual Studio 2022，Release 构建。
- 本地端到端测试使用仓库自带 mock HTTP/Raw/SSH 服务，不依赖真实 API Key 或真实远程主机。
- 远程 SSH 用例默认只验证 `ssh.github.com:443` 的主机密钥协商和进入认证阶段，不提交任何凭据。
- 除非用例明确要求，测试结束后应关闭由用例启动的 PuTTY 进程，并清理临时注册表项、临时配置和产物目录。
- 结果判定：步骤全部完成且预期结果满足则 PASS；任一预期不满足则 FAIL，并保留日志、截图、请求体或窗口状态作为证据。

## 3. 推荐执行顺序

1. TC-A01～TC-A05：确认构建产物和底层测试基线。
2. TC-B01～TC-B08：确认启动、配置及持久化，避免污染后续 UI 测试。
3. TC-C01～TC-C11：使用 mock 服务验证请求体、流式协议、错误处理和隐私边界。
4. TC-D01～TC-D07：在同一 mock 会话中验证 Markdown、命令提取与确认安全。
5. TC-E01～TC-E06：验证窗口布局、焦点、滚动和清空操作。
6. TC-F01～TC-F06：验证多主机、保活、审计、远程握手和站点发布。
7. 任一 P0 用例失败即暂停发布判断；先创建能稳定复现该失败的回归检查，再修复生产代码。
